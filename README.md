# Tsukimera

**Tsukimera** — самостоятельный проект, использующий визуальную оболочку меню и настроек из [Aspksa/JUUNIBI](https://github.com/Aspksa/JUUNIBI). JUUNIBI не изменялся.

## Как запускать на Windows

1. Скачайте архив репозитория и распакуйте в любую папку, в том числе на переносной SSD, с пробелами или кириллицей в пути.
2. Дважды нажмите **Tsukimera.bat**.
3. Браузер откроет локальный интерфейс (обычно `http://127.0.0.1:4173/`). Если порт занят, выберется следующий.
4. Ctrl+C или закрытие окна BAT остановит локальный сервер.

Node.js 22.16+ (рекомендуется 24) используется из системы либо автоматически загружается в `.runtime/node`, по той же схеме, что и в JUUNIBI. Если Node.js уже установлен, `npm install` **не требуется**. После первого запуска приложение работает без интернета.

На Linux/macOS: `node scripts/launch.mjs`. Аргументы: `--no-open`, `--port 4173`.

## Перенесено из JUUNIBI

- Оригинальные CSS-стили JUUNIBI для сайта, меню и дизайн-системы: `web/juunibi-style.css`, `web/juunibi-nav.css`, `web/juunibi-design.css`. Отдельный `tsukimera.css` адаптирует их к чёрно-золотой теме.
- Пункты меню: **Беседа, Дела, Диск, Мозг, Настройки**.
- Режим иконок, группы, скрытие/показ пунктов, изменение порядка и сброс меню.
- Мобильная выдвижная панель и нижний бар с пятью актуальными разделами, поиск по меню, Ctrl+K, Ctrl+B, Ctrl+, и Alt+1–5.
- Десять разделов настроек: **Подключение, Модель, Инструкции, Память, Инструменты, Быстрые команды, Внешний вид, Чат, Данные, О программе**.
- Настройки темы, акцента, масштаба, скругления и меню теперь сохраняются в локальной SQLite `data/tsukimera.db`. Браузерный `localStorage` оставлен только как быстрый рабочий кэш и для одноразового переноса старых значений.
- Параметры моделей, инструкций, памяти, инструментов и быстрых команд сохраняются через локальный API в `data/settings.json` (без ключей и паролей). Есть экспорт/импорт без секретов и простые локальные заметки.
- Сервер слушает только `127.0.0.1`, с ограниченными статическими маршрутами, валидацией настроек, CSP и атомарным сохранением.

## Шрифт и отступы — из Kiyomira

Внешняя оболочка по-прежнему основана на JUUNIBI, но из [Aspksa/Kiyomira](https://github.com/Aspksa/Kiyomira) перенесены **системный моноширинный шрифт**, базовый межстрочный интервал 1.5, единая шкала отступов **4/8/12/16/24/32 px** и адаптивные размеры малого/основного/заголовочного текста. Важные значения взяты из `10-Веб/02-Стиль.css` и `10-Веб/05-ЕдиныйИнтерфейс.css`.

Стили применяются в `web/tsukimera.css` после JUUNIBI CSS без изменения меню и его функций. Существующие варианты масштаба **меньше / обычно / больше** сохранены, как и особые отступы для мобильного режима.

## Полный «Диск» из JUUNIBI

**Диск подключён** к действующему меню Tsukimera и серверу `127.0.0.1`. Это перенос оригинальных модулей [JUUNIBI](https://github.com/Aspksa/JUUNIBI): исходные TypeScript-файлы находятся в `disk-src/web` и `disk-src/server`, оригинальная разметка и оформление в `web/disk.css`. Они компилируются **локально при запуске** встроенным TypeScript-трансформером Node.js 22.16+ (рекомендуется Node 24), **без npm install, Docker и облачных вызовов**. Компилированные файлы — только временные артефакты в `.runtime/disk-built`.

Работают **дерево папок, загрузка файлов и папок с перетаскиванием, поиск по имени и содержимому, режимы плиток/списка/таблицы, избранное, теги и заметки, перемещение и копирование, корзина с восстановлением, версии файлов, дубликаты, проверки целостности, предпросмотр Office/PDF/ZIP/изображений/видео, миниатюры, потоковый ZIP, резервная копия и восстановление, «Жизнь документов» (150 метрик)**. Код хранит исходные ограничения до 500 МБ на файл и 10 000 файлов.

**Место хранения:** `data/disk/` внутри Tsukimera — папка на том же диске/SSD, где расположен проект; переносится вместе с ним. Приложение не сканирует посторонние папки компьютера и не отправляет файлы в Cloud.ru. Вынеси резервные копии на отдельный носитель.

**Связь с «Делами»:** файл можно прикрепить к текущей локальной заметке Tsukimera; связь сохраняется в браузере. История проектов JUUNIBI не импортируется. **Связь с чатом:** функции «Спросить ИИ о файле» и отправка в чат появятся после появления самого ИИ-движка; интерфейс не притворяется, будто облачная модель подключена.

**Безопасность:** исходный `LocalDisk` проверяет имена, пути, размер и SHA-256 файлов; сервер не отдаёт файлы компилятора или внутренние данные напрямую. Сторонние сайты не могут вызывать изменяющие операции. Для старых копий документов используйте встроенную функцию резервирования, но перед запуском импортированного кода обязательно оцените риск и проверьте CI.

## Disk Experience — дополнительные возможности

В развитие JUUNIBI Disk добавлены:

- **Бесшовный дизайн и анимированные переключения** вида/сортировки (учтён `prefers-reduced-motion`).
- **Боковое дерево** раскрывает и запоминает цепочку выбранной папки; **умные папки** фильтруют по имени, пути, расширению и тегам без перемещения оригиналов.
- **Быстрый предпросмотр справа** по одному щелчку (для поддерживаемых файлов); двойной щелчок — полный просмотр.
- **Четыре режима отображения** сохранены; в таблице можно включать колонки «Размер», «Дата», «Папка».
- **Ctrl+K** внутри Диска открывает палитру команд, папок и файлов; вне Диска остаётся общий поиск.
- **Массовое переименование**: шаблон `{name}`, `{ext}`, `{n}`, предварительный просмотр и попытка безопасного отката.
- **Карта пространства** отображает фактический объём файлов в каждой верхней папке. Это не статистика свободного места всего физического SSD.
- **Возобновляемые загрузки** файлов более 8 МБ: куски по 4 МБ сохраняются между запусками сервера. После прерывания нужно **повторно выбрать тот же локальный файл** — браузер не сохраняет доступ к файлам на диске. Неполные загрузки не видны в каталоге; служебные части очищаются через 48 часов.
- **Ссылка на документ для будущего чата**: можно скопировать локальную ссылку на файл; она открывает нужный документ в этой Tsukimera. Отправка в ИИ и ответы с цитированием будут доступны только после интеграции настоящего ИИ-чата, которого пока нет.

Изменения работают на текущем локальном сервере и не требуют новых npm-пакетов, Docker, Ollama или облачных запросов.

По выбранным улучшениям № **1, 2, 4, 5, 6, 7, 9, 13, 14, 15, 16, 17, 23, 29 и 30**:

- **Диск теперь занимает всю ширину рабочей области** справа от меню (больше нет ограничения 1200px/центрирования). Другие разделы интерфейса не меняются.
- Слева дерево папок, в центре расширенная область файлов, справа существующая панель «Жизнь документов» или сведения. Между колонками на широком экране — **две тонкие перетаскиваемые линии**.
- Ширина разделителей сохраняется в браузере (`tsukimera.disk.layout.*`), на небольших экранах автоматически ограничивается ради ширины файлов. Для тонкой настройки: выделите разделитель клавишей Tab и используйте стрелки (16px; Shift — 32px), Home/End; двойной щелчок возвращает стандартную ширину.
- Плитки масштабируются ползунком **«Размер плиток»** (160–360px), выбранный размер запоминается. Адаптивная сетка автоматически использует доступные колонки без горизонтального скролла.
- Имена показываются максимум в две строки в плитке, полное имя доступно при наведении; в таблице и списке — аккуратное многоточие.
- Сохранены системный моноширинный шрифт Kiyomira, чёрно-золотая тема, поиск, локальные файлы, версии, архивы, корзина, все функции из JUUNIBI.
- Адаптивность относительно **ширины самого Диска**, а не только монитора: при широкой области три панели; на ноутбуке папки + файлы и нижняя аналитика; на мобильном — одна колонка, папки выдвигаются кнопкой.
- Отключение анимаций через системное `prefers-reduced-motion`.

Браузерные проверки измеряют реальную геометрию Chrome в разрешениях **1920/1366/390** и проверяют перетаскивание разделителя и сохранение масштаба.

## Жизнь Диска 4.0 — все 150 показателей в двух режимах

**Все старые показатели и 15 разделов сохранены:** серверный модуль `disk-src/server/disk-life.ts` продолжает считать те же 150 метрик по реальным локальным данным. Новый интерфейс лишь улучшает навигацию и отображение.

- **Справа от файлов:** компактная панель с шестью настоящими основными числами, пятью направлениями и предварительным просмотром трёх показателей выбранного раздела.
- **Развернуть:** аналитика занимает всю рабочую ширину «Диска»; дерево папок, файлы и открытые сведения временно скрыты без потери их состояния. Кнопка возврата и Esc возвращают прежний вид.
- **Пять направлений / пятнадцать оригинальных разделов:** «Файлы», «Активность», «Содержимое», «Связи и рекорды», «Состояние». Ни одна группа не удалена.
- **Полная сводка:** шесть оригинальных верхних показателей, затем 10 показателей текущего раздела. Карточки маленькие, средние и широкие; адаптивная сетка 1–4 колонки.
- **Подробности метрики:** при нажатии показываются значение, подтверждённая методика там, где она проверена по исходникам, пояснение из исходного расчёта, локальный набор исходных данных и дата расчёта. Непроверенные формулы не выдаются за точные.
- **Файл-источник:** переход к документу доступен **только** если сервер передал реальный `sourceFileId` конкретного файла — для самого большого/маленького, самого длинного документа и некоторых иных точно установленных показателей. Агрегированные показатели не подставляют вымышленные источники.
- **Графики:** оригинальные графики JUUNIBI сохранены. В развёрнутом режиме для текущей группы они отображаются по мере появления на экране (IntersectionObserver); в компактном режиме графики не перегружают правую панель.
- **Мягкие переходы:** анимации отключаются при системном `prefers-reduced-motion`.

**Новые зависимости, облачные запросы и фоновые процессы не добавлены.** Варианты ширины «Диска» и `Tsukimera.bat` работают как раньше.

## Disk 9.0 — орбитальная Живая карта

Выбранные изменения: **2, 9, 12, 16, 17, 18, 19, 21**.

- **2 — Автоматическое пространство:** высота живой мини-карты вычисляется от количества папок (в пределах 15–33% высоты экрана с адаптивными максимумами). Чем длиннее дерево, тем больше места остаётся папкам. Диск продолжает работать в выдвижной мобильной панели.
- **9 — Автоцентрирование:** при открытии новой папки в дереве мини-карта смещает именно её настоящий узел в центр; обновление содержимого той же папки не сбрасывает ручной масштаб/панорамирование. Текущая папка и её предки попадают в ограниченную выборку даже при большом каталоге.
- **12 — Реальный путь от корня к файлу:** по рёбрам «содержит» строится и выделяется точная цепочка предков. Никакие случайные связи по общим меткам или SHA-256 не выдаются за вложенность.
- **16 — Объём:** лёгкое радиальное освещение узлов и золотое свечение выбранного пути. При высокой плотности используются простые заливки во избежание лишней нагрузки.
- **17 — Световой импульс:** короткий эффект при выборе объекта, не фоновая бесконечная анимация. Уважает настройки reduced-motion.
- **18–19 — Орбиты без наложений:** каждый ребёнок располагается вокруг своего фактического родителя; стабильный детерминированный алгоритм с пространственными корзинами уменьшает пересечения и не нуждается в физическом движке.
- **21 — Раскрытие кластеров:** при переходе на детальный слой или раскрытии кластера узлы плавно перемещаются из старых экранных позиций, новые появляются из центра выбранной группы. Продолжительность ограничена 420 мс; reduced-motion мгновенный переход.
- Сохраняются прежние функции: поиск файлов, меню разделов, большая Canvas-карта, локальные данные, SQLite и резервные копии, 150 показателей аналитики, работа Windows BAT, без Docker/Ollama/новых зависимостей и дополнительных платных обращений к Cloud.ru.

Новые тесты проверяют точные пути от корня до файла, расстояния и стабильность орбит, адаптивную высоту, ограниченность анимации и реальное автоцентрирование в Chrome.

## Disk 8.3 — простое дерево и масштабируемая Живая карта

Левая панель теперь состоит из минимального **дерева папок** и живой Canvas-карты. Из дерева убраны строка «Найти папку», меню сортировки («Закреплённые», «По имени», «По количеству файлов» и т. д.) и значки закрепления: папки показываются по имени, в естественной вложенной иерархии. Ранее сохранённые настройки оформления/закрепления в SQLite не удаляются. Общий поиск по файлам, старые разделы и умные папки остаются доступны отдельно.

- **Синхронизация**: выбор папки в дереве выделяет соответствующий узел мини-карты и его родительскую цепочку. Карта продолжает открывать реальный файл/папку двойным кликом или Enter.
- **Масштаб и перемещение**: колесо изменяет масштаб вокруг указателя, удержание мыши перемещает карту. Клавиши \`+\`, \`-\`, \`0\` также доступны. Кнопка «Сбросить вид» возвращает обзор.
- **Кластеры**: при большом каталоге мини-карта ограничена **70 файлами / 40 папками** в обзорном слое и до **190 файлов / 100 папок** в подробном. Не показанные файлы и папки не исчезают из подсчёта: максимум 12 агрегированных узлов отображают фактическое количество и размер оставшихся объектов. При приближении отображается более подробный слой. Нажатие на кластер фокусирует соответствующую группу. Полный каталог доступен в папках и через поиск.
- **Визуальные различия**: круг — корень Диска, скруглённый квадрат — папка, ромб — файл, шестиугольник — агрегированная группа. Основные цвета чёрно-золотой темы сохранены.
- **Сохранение положения**: масштаб, сдвиг и выбранный фокус сохраняются под ключом \`tsukimera.disk.minimap.view.v1\` через уже существующее SQLite-хранилище настроек и восстанавливаются при повторном открытии.
- **Производительность**: граф перестраивается только при изменении данных или уровня детализации; невидимые узлы и рёбра не рисуются, используется один \`requestAnimationFrame\` по требованию и остановка наблюдателя при закрытии страницы. Высота дерева и карты подстраивается под ширину и высоту экрана.
- **Безопасность данных**: в серверный список допустимых ключей добавлены существовавший ключ настроек разделов и новый ключ мини-карты, чтобы их можно было сохранить и восстановить через SQLite. Самих файлов, версий, связи документов и все **150 показателей** это не меняет. Новых зависимостей и Cloud.ru-запросов нет.
- **Проверки**: добавлены тесты 10 000 файлов и 100 папок (границы модели, полнота кластерных сумм, отсутствие ссылок на несуществующие узлы) и Chrome-проверки масштабирования и сохранения настроек. Старые проверки Windows/Linux/BAT не отключались.

## Disk 8.2 — Живая карта вместо блока «Разделы»

Левая боковая панель стала проще: **сверху иерархия папок, снизу настоящая мини-карта Диска**. Отдельный большой блок «Разделы» больше не занимает место в панели.

- **Карта на Canvas:** мини-карта автоматически пересчитывается из текущих файлов и папок, показывает реальные связи вложенности, дубликатов SHA-256 и общих меток. Отображает общее количество файлов и папок, а выбранный путь выделяется золотым цветом. При больших каталогах мини-карта ограничивает число одновременно отображаемых узлов; полный каталог остаётся доступен через дерево папок и поиск.
- **Навигация:** один клик выделяет узел и показывает его название, объём и количество файлов, двойной клик открывает папку или файл. Клавиша Enter открывает выбранный объект. Кнопка **«Развернуть карту»** запускает прежнюю полноразмерную живую Canvas-карту со всеми её инструментами.
- **Разделы не удалены:** через **«Ещё → Разделы и умные папки»** доступны прежние Избранное, Недавние, Изображения, Документы, Крупные файлы, Корзина и пользовательские умные папки. Их счётчики, переходы, порядок, скрытие и настройка продолжают работать. Все файлы и настройки сохранены.
- **Бережная работа:** мини-карта рисуется только при обновлении каталога, навигации или размера контейнера, без постоянной анимации и дополнительных серверов. Файлы, их версии, SQLite и все **150 показателей** остались без изменений.

## Disk 8.1 — иерархия, разделы и Живая карта

Дополнение к локальному интерфейсу Диска: файлы, их версии, SQLite и все **150 показателей** аналитики не изменяются.

- **Иерархия папок:** вложенные папки связывают тонкие линии; ветви раскрываются с короткой анимацией (при \`prefers-reduced-motion\` без анимации). Дерево прокручивается внутри панели и не вытесняет разделы. Рядом с надписью «Иерархия» появились кнопки «Развернуть все» и «Свернуть все». Родители выбранной папки подсвечиваются на всём пути.
- **Безопасное перемещение:** при перетаскивании отображается целевая папка; недопустимые операции, такие как перенос в саму себя или вложенный каталог, блокируются. Перед реальным перемещением папки пользователь подтверждает действие. Отказ не изменяет каталог.
- **Разделы:** заголовок можно свернуть/раскрыть. Кнопка «Настроить разделы» позволяет показывать/скрывать исходные 6 категорий и менять порядок стрелками. Порядок можно менять и перетаскиванием кнопок. Сохранённые настройки хранятся под отдельным ключом \`tsukimera.disk.sections.v1\` через существующий механизм настроек; переключатель «По умолчанию» восстанавливает исходные категории. Корзина и сами файлы не удаляются при скрытии пункта меню. Активный раздел и категория выделяются, у категорий более различимые иконки.
- **Живая карта:** сохранены существующее окно карты и переходы к папкам/документам. Масштаб узлов теперь зависит от реального числа файлов и объёма данных, с ограничениями для читаемости. При наведении показываются полный путь, число файлов, место на диске, число связей по вложенности, общим меткам и совпадающему SHA-256 (если такие связи есть). Никаких предположительных связей не добавляется.
- **Проверки:** тесты структуры папок, запрета опасных перемещений, порядка/видимости разделов, визуального выбора и исходных связей карты; браузерные проверки на Chrome, CI для Linux и Windows.

Мини-карта в боковой панели **не добавлялась**, поскольку выбраны пункты 24–27, но не 21–23. Canvas-карта по-прежнему доступна через меню «Ещё → Живая карта файлов и связей».

- **Перетаскивание:** папка назначения выделяется, появляющаяся подсказка показывает, куда перемещаются файлы. Системная проверка перемещения остаётся прежней; подсказка сама ничего не перемещает.
- **Краткая аналитика:** в обычном режиме справа только шесть основных показателей и кнопка полного просмотра. При разворачивании доступен прежний интерактивный выбор 5 направлений/15 разделов, поиск, фильтры и новый переключатель **«Все 150»**, позволяющий показать в одной ленте каждую из 150 исходных метрик. Первый клик выделяет объект, второй клик или «Открыть выбранное» открывает файл/папку; \`Enter\` открывает выбранное с клавиатуры. Масштабирование и удержание позиции плавные, при \`prefers-reduced-motion\` анимация отключается.

## Disk 7.0 — надёжность и автоматизация (4, 6, 9, 10, 11, 12, 14, 23)

- **Автопроверка данных:** пока Tsukimera запущена, локальная очередь постепенно проверяет размер и SHA-256 файлов и сохранённых версий, записывая результаты в SQLite. В меню Диска → **Ещё → Фоновая автоматизация** видно, сколько файлов проверено, индексировано и какие ошибки найдены. Исходные файлы не удаляются при подозрении на повреждение.
- **Обслуживание SQLite:** \`PRAGMA optimize\` и \`quick_check\` запускаются периодически (не чаще одного раза за 6 часов работающего сервера), очередь отдаёт приоритет безопасности и не создаёт отдельного процесса или внешних расходов. Фоновые задачи не выполняются при выключенной Tsukimera.
- **Инкрементальное сохранение:** SQLite-схема v3 хранит полные данные каждого файла в \`disk_entries\`, глобальные папки/операции и корзину в \`disk_meta\`, версии — в \`disk_versions\`. Одна операция обновляет только изменённые файлы и папки. Старый \`disk_state\` используется при миграции, но впоследствии не переписывается на каждой операции. Совместимая копия \`data/disk/index.json\` по-прежнему создаётся. Все файлы и их бинарные версии остаются в \`data/disk/objects/\`.
- **Переход с предыдущей версии:** перед созданием новых таблиц в \`data/backups/before-disk-index-*.db\` автоматически создаётся резервная копия SQLite с помощью встроенного online-backup API. Обновление схемы выполняется локально. Перед обновлением важного Диска сделайте отдельную резервную копию всей папки \`data/\` на другой носитель, когда программа остановлена.
- **FTS5:** поиск по содержимому использует полнотекстовый индекс \`disk_fts\` и локальный кеш извлечённого текста \`disk_text_cache\` по SHA-256. Кеш сохраняется между запусками. Поиск работает по **началу слов** (поддерживает кириллицу), а не по произвольной подстроке внутри слова. Старые документы индексируются постепенно после запуска: пока в панели автоматизации есть ожидающие файлы, результаты поиска по тексту могут быть неполными. При новой версии файла старая запись полнотекстового индекса удаляется сразу. Данные документов не отправляются в Cloud.ru.
- **Очередь:** одно небольшое задание за проход, тайм-ауты и интервалы между заданиями; при ошибке следующая попытка происходит позже. Результаты индекса и аудита сохраняются в SQLite, очередь запускается заново при следующем открытии программы. \`GET /api/disk/automation\` возвращает текущее состояние; \`GET /api/disk/search?q=...\` — совпадения и статус индекса. Никаких npm-пакетов.
- **Большие папки:** в режимах «Список» и «Таблица» при большом количестве файлов DOM содержит только видимое окно с запасом строк; в плитках страницы подгружаются автоматически при прокрутке. Выбор, файлы и сортировка не меняются.
- **Умные папки 3.0:** в «Диск → Ещё → Умные папки» можно задать от одного до четырёх условий и выбрать «все условия (И)» / «любое условие (ИЛИ)». Поля: имя, путь, расширение, тег, размер в МБ, дата загрузки, избранное. Старые правила автоматически читаются и продолжают работать. Фильтры ничего не перемещают и не удаляют.

Текущее ограничение: автоматическая текстовая индексация охватывает поддерживаемые текстовые и офисные файлы до 20 МБ; сканы PDF без текстового слоя не распознаются. Для OCR понадобится отдельное согласованное решение. Все **150 прежних показателей** аналитики сохраняются.

Личные инструкции и опасные действия требуют явного подтверждения. Видимый статус показывает сохранение, успех или ошибку. Отдельный платный запрос на генерацию не выполняется.

Вместо двух одинаковых списков — **один каталог** с поиском по названию/ID, кнопками «Сделать основной/запасной» и обновлением. После проверки ключа полученный список переиспользуется без второго запроса. Список грузится автоматически, только если сервер сообщает о настроенном ключе. Секрет остаётся в оперативной памяти сервера; приложение не пишет его в SQLite, браузер и экспорт.
- **SQLite:** компактный центр с целостностью, размером, таблицами и числом файлов, версий, заметок и настроек; сохраняется кнопка подробной проверки.
- **Автоматические локальные резервные копии SQLite:** во время работы проекта приблизительно раз в **24 часа** (первая проверка после запуска с короткой задержкой) создаётся корректный online-снимок `data/backups/settings-auto-*.db`. Проверяется свободное место, копирование пропускается при недостатке пространства или при размере базы более **256 МБ**; максимум **7 снимков** и **512 МБ** суммарно. **Только** старые файлы `settings-auto-*` подпадают под удаление — ручные копии, копии до миграции/восстановления и файлы Диска не трогаются. Копирование прекращается при закрытии сервера; отдельный фоновый сервис не запускается.
- **Важно:** эти автоматические `.db`-снимки сохраняют **SQLite**, но **не** бинарное содержимое `data/disk/objects` и его версии. Для полной защиты документов отдельно экспортируйте Диск и делайте копию всей `data/` на другой физический носитель. Хранилище проектов и API-ключи не отправляются в Cloud.ru.

Никаких новых зависимостей, Docker, Ollama или дополнительных сервисов.

## Настройки 3.0: безопасность, Cloud.ru и диагностика

После выбора ветки Settings 3.0 обновите проект и перезапустите \`Tsukimera.bat\`.

### Что реально работает

- Исправлен перенос устаревших \`juunibi.disk.*\` → \`tsukimera.disk.*\` и доступность переключения исходного Markdown \`tsukimera.disk.mdRaw\`. Основное хранилище настроек: \`data/tsukimera.db\`, browser localStorage — временное зеркало.
- При загрузке архива «Настройки → Данные» сервер проверяет формат и значения, создаёт самостоятельную резервную копию всей SQLite \`data/backups/settings-restore-*.db\`, затем **одной транзакцией** восстанавливает настройки, заметки и их связи. Неверный архив не должен вносить частичных изменений. Файлы и редакции Диска по-прежнему экспортируются отдельно.
- «Проверить целостность SQLite» показывает быстрый результат \`PRAGMA quick_check\`, версию схемы, размер, таблицы, количество записей и сохранённых резервных копий.
- Поиск по настройкам находит отдельные параметры и разделы; сохранение одного значения не уничтожает черновики в других текстовых полях.
- Разделы помечены по доступности: «Работает», «Частично» и «Не подключено». Дизайн по умолчанию остаётся чёрным с золотым акцентом; новые правила локализованы внутри Settings.

### Cloud.ru Foundation Models — настоящий список моделей, но не платный чат

Реализован официальный OpenAI-совместимый endpoint Cloud.ru:
\`https://foundation-models.api.cloud.ru/v1/models\` (**GET**).

1. Создайте API-ключ Foundation Models в сервисном аккаунте Cloud.ru. В «Настройки → Подключение» введите Key Secret и нажмите **«Проверить подключение»**. Вы увидите количество моделей или точную ошибку соединения.
2. В разделе «Модель» введите название вручную либо выберите его из актуального списка, используя поиск. Сохраните основную и запасную модели.
3. Ошибки 401, 402, 403, 429 и 5xx показываются с различными причинами. Программа не делает повторных запросов автоматически и не вызывает модель для диагностики.

**Безопасность:** ключ находится только в оперативной памяти работающего локального сервера. Он не сохраняется ни в SQLite, ни в браузерной localStorage, ни в резервной копии. После перезапуска приложения введите ключ повторно. Альтернатива для запуска с заранее заданным ключом — переменная окружения \`CLOUD_RU_FOUNDATION_MODELS_API_KEY\`. Устанавливайте её только безопасным способом и не включайте в публичные репозитории. Кнопка «Отключить» очищает ключ в этом запуске. Настройки не обращаются к платному \`POST /v1/chat/completions\`.

### Память и инструменты

Реальная локальная память **заметок и их документных ссылок** уже в SQLite. Поиск по смыслу, фоновые сводки, автоматическое извлечение фактов и исполняемые ИИ-инструменты **ещё не реализованы**. Панель показывает это явно; включение сохранённых предпочтений не может включить несуществующий модуль. Ручной доступ владельца к локальному Диску не отключается настройками будущего ИИ. При проектировании ИИ-исполнителя необходимо применять отдельное подтверждение и серверные проверки реальных действий, до этого включать привилегированные инструменты нельзя.

Достоверные статусы доступны через локальные \`GET /api/capabilities\`, \`GET /api/storage/diagnostics\`, \`GET /api/cloud/status\`, \`GET /api/cloud/models\`. Последний запрос требует API-ключ, полученный сервером, и обращается к внешнему Cloud.ru (без инференса).

Тесты \`npm test\` проверяют SQLite-снимок до восстановления, атомарность, сохранность пользовательских настроек и заметок, обработку ошибок Cloud.ru и отсутствие ключей в БД. Браузерный тест Chrome проверяет 10 разделов, поиск и отсутствие потери черновиков. Новых npm-зависимостей нет.

## Tsukimera 2.0 — пункты 5, 14 и 17

### 5. Перенос настроек в SQLite
Тема, акцент, размеры панелей и плиток, порядок меню, закрытые группы настроек, режим Диска, умные папки, выбранная аналитика и другие разрешённые предпочтения хранятся в таблице `user_preferences` внутри `data/tsukimera.db`. Существующие ключи JUUNIBI автоматически нормализуются сборщиком Диска и сохраняются в той же SQLite.

- При первом открытии сайта старые настройки браузера копируются в SQLite **один раз**. На следующих запусках SQLite считается источником данных и восстанавливает интерфейс даже при использовании другого браузера или ПК с тем же SSD.
- Браузерный кэш сохраняется для мгновенного отклика управления, но обновления одновременно отправляются в локальный API. При проблеме записи интерфейс предупреждает об этом.
- Перед изменением схемы существующей SQLite приложение создаёт копию базы в `data/backups/before-preferences-...db`. Не переносите работающий файл SQLite без остановки приложения.
- На сервер принимаются лишь заранее разрешённые ключи оформления и Диска. Сессии незавершённых загрузок, секреты и произвольные данные браузера в эту таблицу не попадают.
- Для теста API: `GET /api/preferences`, `POST /api/preferences/initialize`, `PUT /api/preferences`. Исторические JSON-экспорты и локальные заметки остались совместимыми.

### 14. Живая Canvas-карта Диска

В одном окне видны реальные узлы папок и файлов, линии вложенности, совпадения по SHA-256 и общие пользовательские метки. На больших каталогах отрисовывается **до 110 папок и 240 файлов**; точные общие размеры и общее количество файлов показываются отдельно. Это ограничение визуализации, а не хранения: остальные файлы продолжают быть доступны в Диске. Canvas ограничивает масштаб устройства, не держит фоновую анимацию после закрытия окна и учитывает настройки уменьшения движения.

### 17. Интерактивные графики Жизни Диска
В **Жизни Диска → Развернуть → Нажать на показатель** график с существующими сериями данных теперь поддерживает приближение и отдаление, перемещение по точкам, управление стрелками, подсказки значений при наведении и переход к подтверждённому документу-источнику, если ID источника предоставлен сервером. Для агрегированных метрик ссылки на конкретные документы не выдумываются. Значения всех **150 показателей в 15 группах** рассчитываются прежним кодом, а график только отображает полученные данные.

## SQLite — локальная база и сохранение данных

Сервер при запуске использует встроенный модуль **Node.js `node:sqlite` (Node >=22.16)** — без npm, Python, Docker или отдельной СУБД. Основная база: **`data/tsukimera.db`** на том же SSD, что и Tsukimera.

- **Сохраняется:** настройки, весь индекс Диска (папки, метки, корзина, история и редакции), индекс файлов, заметки и ссылки между заметками и файлами. Файлы и все их бинарные версии остаются в **`data/disk/objects/`**, а их каталог и связи индексируются в SQLite. Старые `data/settings.json` и `data/disk/index.json` остаются как совместимые копии, но база является источником истины.
- **Перед первым переносом:** если обнаружены старые данные, программа сначала копирует **`settings.json`**, **всю папку `data/disk/`** вместе с объектами и редакциями, а также незавершённые загрузки `data/uploads/` в **`data/backups/before-sqlite-…/`**. Если копирование не удалось (например, мало места на SSD), SQLite не запускается, исходные данные не удаляются. Копия на том же SSD защищает от ошибки переноса, **но не от поломки носителя** — сделайте отдельную внешнюю копию.
- **Заметки из браузера:** при первом открытии сайта заметки `localStorage` импортируются в SQLite по ID без повторов. Исходный `localStorage` остаётся как страховочная копия; дальнейшие создания, удаления и связи заметок сохраняются через локальный API SQLite. При переключении на другую базу идентификатор экземпляра предотвращает молчаливую потерю локальных заметок.
- **Резервные копии:** прежний экспорт настроек по-прежнему сохраняет заметки и параметры интерфейса; отдельный экспорт Диска включает объекты и редакции. Для переносимости скопируйте всю папку `data/` на другой носитель при **остановленном** сервере либо сохраните оба экспорта. GitHub намеренно игнорирует `data/`.
- **Проверить:** откройте Настройки → Данные: там показывается активная SQLite, количество файлов, заметок и редакций, а также путь первой резервной копии. API: `GET /api/storage`.

Все 150 показателей «Жизни Диска», 15 групп, оригинальный интерфейс и правила хранения документов сохраняются. Встроенная SQLite в Node 22 находится в экспериментальном статусе API, поэтому оставлены совместимые JSON-снимки и тесты на Windows и Linux.

## Улучшения: надёжность, аналитика 5.0 и связи по ID

- Настройки сохраняются последовательными транзакциями: одновременные PATCH/PUT больше не теряют изменения из других полей.
- Возобновление загрузки после повторного выбора файла дополнительно проверяет SHA-256 первых и последних 64 КБ. Это защита от случайной подмены при одинаковых имени, размере и времени изменения, но не замена полной контрольной суммы файла; для важных данных используйте резервную копию.
- «Жизнь Диска 5.0» ищет показатели по всем 15 разделам, показывает фильтры «Все / С данными / Без данных» и прозрачную статистику охвата анализа. Исходные 150 показателей и их расчёты не менялись.
- Ссылки между заметками и файлами основаны на неизменных идентификаторах: переименованный файл получает актуальное название; удалённые ссылки отмечаются, а файлы в корзине обозначаются отдельно. Переход к другой ссылке работает прямо внутри открытого Диска.
- Резервная копия настроек теперь включает **локальные параметры просмотра Диска и умные папки**, но **не содержит байтов документов**. Полную копию самих файлов с редакциями необходимо экспортировать отдельно из Диска. Для полного переноса сохраните оба файла.

## Что ещё не перенесено

Разделы **«Модули», «Телефон», «Обновление»** удалены с их страницами и из боковой и мобильной навигации. Сохранённые настройки порядка меню из старых версий автоматически очищаются при отображении.

Это **готовая оболочка интерфейса**, а не копия ИИ-движка JUUNIBI. Модель Cloud.ru, потоковый чат и RAG пока не реализованы. Файловый менеджер «Диск» работает, SQLite подключена для локального хранения и связей. Разделы меню открываются и показывают честный статус. Ни один переключатель «Инструменты» или «Память» не запускает действия без реальной последующей реализации. API-ключи приложение **не запрашивает и не хранит**.
